# toolsmith (pi)

Stops agents from writing throwaway helper scripts (long heredocs,
`python3 -c` one-liners, scratch `.py` files). The agent reuses a cataloged
CLI tool or has a subagent build one, so the next session can find it.

This is a pi-native version of Jesse Vincent's
[toolsmith plugin](https://github.com/prime-radiant-inc/toolsmith) (MIT,
based on `7e45f7f`). The upstream pi port, generated by everyharness, only
injected a bootstrap line and had no subagent, so it fell back to "write
it yourself".

## What it adds

| Piece | What it does |
|---|---|
| `toolsmith_search` tool | Keyword search over the global catalog and the current git project's catalog. |
| `toolsmith` tool | Runs a headless child `pi --mode json -p` with the toolsmith instructions. The child finds, extends or writes a tool, verifies it, installs it with `toolsmith-repo`, and returns `tool: / catalog: / usage: / status: / mutates: / verified: / assumed: / note:`. Progress streams into the tool row, and the child's token usage is added to the session. |
| Prompt rules | `promptGuidelines` on the `toolsmith` tool: search first, delegate instead of scripting, dry-run if the tool mutates, quote the catalog line. These are part of the system prompt, so they persist and stay cache-friendly. |
| Nudge | A `tool_call` hook holds the **first** attempt at a helper script and tells the agent to search or delegate. This covers a `bash` call with a 6+ line interpreter heredoc, `-c`/`-e` code, or a heredoc into a script file, and a `write` of a 6+ line script into a temp dir or outside any git repo. Re-running the identical call lets it through, for mission work or when the user asked for a script. |
| `/toolsmith [words]` | Lists or searches cataloged tools. `/toolsmith nudge on\|off` toggles the nudge for the session. |

## Child agent

- It uses the caller's current model and thinking level. Override with
  `TOOLSMITH_MODEL=provider/id[:thinking]` (e.g. a cheaper model).
- It runs clean: `--no-extensions --no-skills --no-context-files --no-mcp
  --no-approve`, with only `read,bash,edit,write`. There's no recursion
  into toolsmith, no herdr, and no AGENTS.md.
- `bin/` is put on its `PATH`, so `toolsmith-repo` resolves.
- It times out after 20 minutes. Aborting the caller's turn kills it.

## Files

- `index.ts`: the extension.
- `bin/toolsmith-repo`: vendored unchanged from upstream. It owns the tools
  repo at `~/.local/share/toolsmith/tools` (a git repo with `bin/`,
  `CATALOG.md`, and per-project scopes under `projects/`).
- `instructions/toolsmith-agent.md`: the child's system prompt, rewritten
  for pi from upstream `agents/toolsmith.md`.
- `instructions/authoring-standards.md`: the upstream tool standards, plus
  tailoring for this machine. Python tools that need packages (Pillow,
  pypdf, ...) are uv scripts with PEP 723 inline metadata, and
  mise-managed CLIs are preferred.
- `instructions/reply-format.md`: the upstream reply format, plus a
  `usage:` line.

## Environment

- `TOOLSMITH_NUDGE=off`: disable the nudge.
- `TOOLSMITH_MODEL`: the child's model, as above.
- `TOOLSMITH_TEST_REPO=<dir>`: use a scratch tools repo (honored by
  `toolsmith-repo`; for testing).

## Test

```bash
TOOLSMITH_TEST_REPO=$(mktemp -d)/tools pi -p --no-session --no-extensions \
  -e ~/.pi/agent/extensions/toolsmith/index.ts \
  "Make an A4 PDF from a.jpg and b.jpg, b rotated 180°"
```
